演示 axios 拦截器的注册、移除（eject）与清空操作，理解 handlers 数组管理机制

什么是拦截器？

Axios 拦截器是一种全局请求/响应预处理机制，可以在请求发出前或响应到达后执行自定义逻辑。

类型注册方法用途
请求拦截器axios.interceptors.request.use()添加 Token、日志
响应拦截器axios.interceptors.response.use()错误处理、数据转换

为什么需要移除？

常见场景：

  • 测试时需要隔离全局拦截器
  • Token 过期后刷新并重新注册
  • 动态切换不同拦截器配置
  • 防止内存泄漏（组件卸载时清理）

use() 返回什么？

每次调用 use(onFulfilled, onRejected) 会返回一个数字 ID：

const id1 = axios.interceptors.request.use(fn1); const id2 = axios.interceptors.request.use(fn2); console.log(id1); // → 0 console.log(id2); // → 1

这个 ID 就是后续 eject(id) 的参数。

handlers 数组是什么？

Axios 内部用数组存储拦截器，每个 use() 调用在数组末尾添加一项，返回值就是该项的索引。

// 注册两个请求拦截器 const id1 = axios.interceptors.request.use(fnA); // handlers[0] const id2 = axios.interceptors.request.use(fnB); // handlers[1] console.log(axios.interceptors.request.handlers); // [ [interceptor], [interceptor] ]

eject 后数组变化

const id1 = axios.interceptors.request.use(fn1); // → handlers[0] const id2 = axios.interceptors.request.use(fn2); // → handlers[1] axios.interceptors.request.eject(id1); // handlers → [ null, [interceptor] ] // 注意：eject 后数组长度不变，该位置变为 null const id3 = axios.interceptors.request.use(fn3); // handlers[2] — 新 ID 不会复用 // handlers → [ null, [interceptor], [interceptor] ]

查看活跃拦截器

// 过滤出非 null 的拦截器 const active = axios.interceptors.request.handlers .filter(Boolean) .map(h => h.fulfilled?.name || 'anonymous'); console.log(active); // ['请求拦截器 #1', '请求拦截器 #2']

ID 分配规则

操作handlers 变化返回值（ID）
use(fn1)[ [interceptor] ]0
use(fn2)[ [interceptor], [interceptor] ]1
eject(0)[ null, [interceptor] ]—
use(fn3)[ null, [interceptor], [interceptor] ]2
clearAll()[ ]—

⚠️ eject 后新注册的 ID 不会复用被 eject 的索引，而是继续递增。

eject 推荐

axios.interceptors.request.eject(interceptorId); axios.interceptors.response.eject(interceptorId);

✅ 推荐：语义明确、安全性高

delete 可用

delete axios.interceptors.request.handlers[interceptorId]; delete axios.interceptors.response.handlers[interceptorId];

⚠️ 直接操作数组，与 eject 效果相同，但不推荐

handlers = [] 清空全部

axios.interceptors.request.handlers = []; axios.interceptors.response.handlers = [];

⚠️ 一次性清空所有拦截器，常用于测试环境

use 返回值必须保存

// ❌ 错误 axios.interceptors.request.use(onFulfilled); // 如果不保存返回值，无法后续移除 // ✅ 正确 const id = axios.interceptors.request.use(onFulfilled); // 保存到变量、Map 或数组中

❌ 常见错误：没有保存 ID，后续无法移除

方法对比表

方法作用范围推荐场景安全性
eject(id)单个拦截器日常使用✅ 高
delete handlers[id]单个拦截器备用方案⚠️ 中
handlers = []全部拦截器测试隔离⚠️ 中
handlers.splice(id, 1)单个拦截器不推荐❌ 低

场景一：测试环境隔离

// jest beforeEach beforeEach(() => { // 每个测试前清除全局拦截器，确保测试隔离 axios.interceptors.request.handlers = []; axios.interceptors.response.handlers = []; });

适用：单元测试、集成测试，确保测试之间互不干扰

场景二：Token 动态刷新

let reqId = null; let resId = null; function setup(token) { // 1. 移除旧的拦截器 if (reqId !== null) axios.interceptors.request.eject(reqId); if (resId !== null) axios.interceptors.response.eject(resId); // 2. 添加新的拦截器 reqId = axios.interceptors.request.use((config) => { config.headers.Authorization = `Bearer ${token}`; return config; }); } // 登录后设置 Token setup(newToken); // 刷新 Token 时重新设置 setup(refreshedToken);

场景三：React 组件卸载清理

import { useEffect } from 'react'; function MyComponent({ token }) { let interceptorId; useEffect(() => { interceptorId = axios.interceptors.request.use((config) => { config.headers.Authorization = `Bearer ${token}`; return config; }); // 组件卸载时清理拦截器，防止内存泄漏 return () => { axios.interceptors.request.eject(interceptorId); }; }, [token]); return <div>...</div>; }

场景四：创建无拦截器的 axios 实例

// 方法1：清空拦截器 const cleanApi = axios.create(); cleanApi.interceptors.request.handlers = []; cleanApi.interceptors.response.handlers = []; // 方法2：复制配置但排除拦截器 const cleanApi2 = axios.create({ ...axios.defaults, // 不复制 interceptors });
