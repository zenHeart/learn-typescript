TypeScript 模块声明扩展与覆盖

核心问题

如何扩展或覆盖第三方模块的类型定义，而不修改原库？例如：给 Express 的 Request 对象添加自定义属性。

1原始库类型不完整或不满足需求
↓
2使用 declare module 扩展类型
↓
3或使用 interface extends 创建新类型
↓
4TS 4.9+ 可用 satisfies 保持推断同时验证

五种扩展方法速查

方法是否修改原类型适用场景
declare module否扩展 npm 包类型
interface extends否创建扩展类型
declare global否全局命名空间扩展
satisfies否类型验证 + 保持推断
module 覆盖完全覆盖替换原类型

实战场景

🔌 Express Request

添加 userId、authToken 等自定义属性到 Express 请求对象

📡 Axios 配置

扩展 AxiosRequestConfig 添加 _retryCount 等内部字段

⚛️ React Props

给所有 DOM 元素添加 data-testid 等测试属性

🔷 Vue 组件

在 ComponentCustomProperties 添加全局属性

关键原则

1. interface 可以合并，type alias 不能合并
2. 子元素的 z-index 再高，也不能超出父层叠上下文的边界
3. satisfies 保持类型推断 + 类型检查，两者兼得
4. 尽量扩展而非覆盖，保持对原库的兼容性

declare module 扩展接口

// types/express-custom.d.ts
import 'express';

declare module 'express' {
  interface Request {
    userId?: string;
    authToken?: string;
    isAdmin?: boolean;
  }
}

// 使用时
app.get('/profile', (req, res) => {
  console.log(req.userId);  // ✅ 类型安全
});

多次声明自动合并

// 第一次声明
declare module 'my-library' {
  interface Config {
    timeout: number;
  }
}

// 第二次声明（会自动合并）
declare module 'my-library' {
  interface Config {
    retry?: number;      // 新增字段
    onSuccess?: () => void; // 新增字段
  }
}

// 合并后 Config = { timeout: number; retry?: number; onSuccess?: () => void }

interface extends 扩展

import { OriginalType } from 'some-library';

// 创建新类型，不修改原类型
interface ExtendedType extends OriginalType {
  additionalProp?: boolean;
  nestedConfig?: {
    enabled: boolean;
    timeout: number;
  };
}

// 使用新类型，原始类型不受影响
const config: ExtendedType = {
  prop: 'original',
  additionalProp: true,
};

函数重载合并

declare module 'calculator' {
  function calculate(a: number, b: number): number;
}

// 扩展重载签名
declare module 'calculator' {
  function calculate(
    a: number,
    b: number,
    options?: { precision?: number }
  ): number;
}

declare global

// global.d.ts
declare global {
  namespace MyLibrary {
    interface ExtendedConfig {
      timeout?: number;
      retries?: number;
    }
  }
}

export {};  // 使其成为模块文件

⚠️ 必须有 `export {}` 使文件成为模块，才能使用 `declare global`

Vue 组件全局属性

// types/vue-custom.d.ts
import { ComponentCustomProperties } from 'vue';

declare module '@vue/runtime-core' {
  interface ComponentCustomProperties {
    $myPlugin: {
      getVersion: () => string;
      config: Record<string, unknown>;
    };
  }
}

React DOM 属性扩展

// types/react-custom.d.ts
import 'react';

declare module 'react' {
  interface DOMAttributes<T> {
    // data-* 属性（React 自带，但显式声明更明确）
    'data-testid'?: string;
    'data-cy'?: string;
    
    // 自定义事件
    onDoubleClick?: React.MouseEventHandler<T>;
  }
}

deep extends — 嵌套对象

// 原始类型
interface OriginalConfig {
  database: {
    host: string;
    port: number;
  };
}

// 扩展嵌套对象
type ExtendedConfig = OriginalConfig & {
  database: OriginalConfig['database'] & {
    ssl?: boolean;
    connectionLimit?: number;
  };
};

satisfies 操作符（TS 4.9+）

satisfies 在保持类型推断的同时验证类型是否符合预期。 

import type { Config } from 'some-library';

// 使用 satisfies：保持推断 + 类型检查
const myConfig = {
  prop: 'value',
  newProp: 123
} satisfies Config & { newProp: number };

// myConfig.prop 仍然是 string 类型
// myConfig.newProp 被验证为 number
console.log(myConfig.prop.toUpperCase());  // ✅ 'VALUE'
console.log(myConfig.newProp.toFixed());    // ✅ '123'

as vs satisfies 对比

❌ as 类型断言

const myConfig = {
  prop: 'value',
  newProp: 123
} as Config;

// myConfig.prop 变成 Config['prop']
// 可能丢失 string 字面量推断
console.log(myConfig.prop.toUpperCase());
// ❌ Error: toUpperCase 不存在

✅ satisfies 验证

const myConfig = {
  prop: 'value',
  newProp: 123
} satisfies Config;

// myConfig.prop 保持 string 类型
console.log(myConfig.prop.toUpperCase());
// ✅ 'VALUE' — 推断保留

satisfies 适用场景

场景推荐原因
配置对象验证satisfies保持字面量推断
类型覆盖/替换as明确要替换类型
部分扩展第三方库declare module不改变原类型
创建新类型extends组合多个类型

五种方案对比

方案修改原类型运行时影响推荐场景
declare module + interface否无扩展 npm 包类型
interface extends否无需要新类型
declare global否无全局命名空间
module 覆盖完全替换可能有原类型完全错误

常见错误

错误 1：type alias 无法合并

❌ 错误：type 不能合并
type Config = { x: number };
type Config = { y: string }; // Error: Duplicate identifier

✅ 正确：用 interface
interface Config { x: number; }
interface Config { y: string; } // 自动合并

错误 2：declare global 没有 export

❌ 错误：没有使文件成为模块
declare global {
  namespace Config {}
}

✅ 正确：添加空的 export
declare global {
  namespace Config {}
}
export {};

判断题

1. interface 和 type alias 都可以合并？

✓ 正确
✗ 错误

答案：错误 — 只有 interface 能合并，type alias 不能合并

2. satisfies 和 as 的区别是什么？

satisfies 会丢失类型推断
satisfies 保持推断同时验证，as 只做断言
两者完全等价

答案：satisfies 保持类型推断同时验证类型，as 直接断言类型

3. declare global 必须配合什么使用？

export default
export {} 使文件成为模块
import 语句

答案：declare global 必须配合 export {} 使文件成为模块

4. 将方法与适用场景连线：

declare module → 创建新类型
declare module → 扩展 npm 包
extends → 创建新类型
